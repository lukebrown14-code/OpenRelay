# Stage 6 offline protocol — selective assembly (6C)

**Date:** 2026-09-24.
**Scope:** offline validation of the 6C assembly layer before any model spend
(stage6-plan §9). Zero model calls; zero network calls.

## What is validated

The assembly stack added for 6C:

| Module | Responsibility |
|---|---|
| `lib/handoff/builder.ts` | Deterministic handoff builder: explicit inputs only, sha256 evidence digests, bounded (≤512 B) recovery excerpts with truncation flags, un-labeled inputs become `unknown` provenance (never guessed), mandatory fields enforced |
| `lib/memory/select.ts` | Conservative note selection: exact-path overlap with v3-verified request paths or explicit task reference; abstains on retired/stale/no-reference/conflict/considered-cap; conflict retracts both overlapping notes; cap 2, stable tie-break |
| `lib/assemble/index.ts` | Combined renderer: handoff (mandatory, never truncated) + memory notes; complete UTF-8 byte accounting including headers/provenance; duplicate suppression against the actual v3 packet bytes; omission ledger with reasons; safe fallbacks |
| `lib/assemble/budgets.ts` | Frozen budgets (plan §7): notes considered ≤100, selected ≤2, memory ≤2 KiB, handoff ≤6 KiB, total ≤12 KiB, hashing ≤32 files/4 MiB, recovery excerpt ≤512 B, prep target 100 ms / abandon 250 ms |

## Frozen holdout

- Location: `plugins/token-efficient/test/fixtures/stage6-holdout/`
- Cases: **12 positive + 8 negative**, generated by
  `plugins/token-efficient/scripts/stage6-holdout.ts --generate` and then **frozen**.
- Integrity: per-case tree hash (sorted repo-relative paths + per-file sha256) and a
  manifest hash over the full expectation set.
  **Frozen manifest hash:**
  `5a4a6c8f7f89db73d7c1e26d73cfc696d9fea8e825fe81237da262c6981f11d9`
- The scorer (`plugins/token-efficient/scripts/score-stage6-holdout.ts`) verifies both
  hashes before scoring and aborts on drift. Expectations were written from the plan
  rules, not from observing the implementation.

### Case classes

Positive (usable evidence expected): accepted-plan constraints; failed-verification
details; partial progress; restart recovery; concurrent tasks (leakage check);
worktree change (stale note abstains, handoff usable); current referenced note;
v3-packet dedup; path-overlap selection; cap + stable tie-break; evidence recovery
excerpt; conflict abstention with usable handoff.

Negative (abstain or fall back): missing mandatory evidence; oversized mandatory
handoff; oversized note; malicious note content (injection markers); unrelated task;
ambiguous stale-validity note; cross-task leakage attempt; malformed artifacts.

## Scoring procedure

1. `bun plugins/token-efficient/scripts/score-stage6-holdout.ts` — verify hashes, run
   each case twice (cold + warm), evaluate preregistered expectations.
2. Gates (§9): zero silent losses; usable evidence ≥10/12 positives (safe fallback
   does not count as coverage); zero accepted stale-critical claims, cross-task
   leakage, or unintended model calls; 8/8 negatives abstain/fall back; payload
   bounds hold; no exception escapes; prep p95 ≤100 ms target, 250 ms abandon.

## Retune discipline

The holdout is frozen; selection thresholds and budgets may not be adjusted after
reading holdout outcomes and the same set reused for a PASS claim. The first full
scoring run and every subsequent run are recorded in `offline-results.md`; runs after
implementation bug fixes are labeled **repeat**, never presented as the fresh result.
